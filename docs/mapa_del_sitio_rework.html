Las páginas viejas no se borran: su Contenido Web cambia a un aviso corto con un botón a la página nueva, así los enlaces que ya circulan (QR, redes, correos) siguen sirviendo. Las versiones /en/… son las mismas páginas en el idioma inglés y se resuelven solas. Los enlaces del pie de página (Rector, Modelo educativo, etc.) son de iteso.mx y no se tocan.

Para decidir antes de construir

  1. Especies como Contenidos Web. Para que una persona sin formación técnica agregue o corrija una especie, cada especie tiene que ser un Contenido Web con la Estructura "Especie" (son ~400: 255 árboles, 48 orquídeas, aves, suculentas y flores). A mano no es viable: la propuesta es cargarlos una vez por la API de Liferay con tu sesión, desde un script con plan en seco. Hay que confirmar que tu usuario puede crear Contenidos Web por la API. Si no se puede, la Colección seguiría leyendo el JSON de Documentos y Medios (lo que ya hace el prototipo), pero entonces agregar una especie dependería de regenerar ese archivo.
  2. URLs nuevas. Las fichas quedarían en campuslab.iteso.mx/w/<especie> (Liferay 7.4 pone ahí las páginas de visualización; hay que confirmarlo en el sitio) y las páginas sin el sufijo "-iteso" o "-de-casa" (/aves, /orquideas). ¿Te parecen bien o prefieres conservar las de hoy?
  3. Las aves ganan ficha propia. Hoy no tienen ficha: viven como texto dentro del artículo de 230 KB. Con la Plantilla "Especie" tendrían la misma ficha que árboles y orquídeas (foto, estatus, canto en xeno-canto). ¿Va?
